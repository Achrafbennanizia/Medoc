The MeDoc Dentist website

A product site in English, French and Arabic that shows the real app, real documents and prices in dirhams, with no trackers.

The problem

MeDoc Dentist needed a place where a dentist in Morocco can see the program, compare the editions and ask for a demo.

It had to read well in French and Arabic, with Arabic laid out right to left. It had to show only what the app really does, with prices in dirhams. And it had to respect visitors: no tracking, and nothing collected beyond what they choose to send.

What we built

A website with one page for each question a dentist asks: what the program does, which edition fits, what it costs, what Moroccan law says about patient data, how the program keeps that data safe, and how to get a demo.

Every screen on the site is a capture of the running app with demo data. Every sample document is a real PDF made by the app's own code: Moroccan invoices, a credit note, prescriptions and medical certificates, in French and Arabic.

The demo form sends the request to our contact service. If that service can't be reached, the visitor's own mail app opens with the message ready to send.

How the contact service works

How it works

The site is a single-page app in React 19 and TypeScript, built with Vite.

It uses hash routes, such as #/pricing, so it runs on static hosting with no server of its own. Older links still open the page that now holds their section.

French is the default language. The French and Arabic copy is typed against the English, so a missing translation stops the build instead of reaching a visitor. In French and Arabic, numbers and dates follow the Moroccan format.

Arabic switches the whole layout to right to left. The theme and the text direction are set before the first paint, so the page does not flash.

Fonts are served from the site itself. There are no analytics, no third-party trackers and no third-party scripts.

The only cookies are three first-party ones, for the language, the theme and the cookie notice, written when the visitor makes a choice.

GitHub Actions builds the site. A pull request is type-checked and built but never published; a push to the main branch publishes it to GitHub Pages.

Results

  • Live in English, French and Arabic, with Arabic laid out right to left.
  • 26 screens of the real app, captured with demo data.
  • Real PDF documents from the app, not mock-ups.
  • No analytics and no third-party trackers.
  • Every change is type-checked and built before it goes live, and a push to the main branch publishes it with no manual steps.

What's next

Once our first pilot practices have used MeDoc Dentist, we will add their stories, with their permission.
