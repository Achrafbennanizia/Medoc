MeDoc Dentist

Practice software that runs on the practice's own computers, works without the internet and keeps patient data encrypted.

The problem

In a dental practice that works on paper, each patient lives on a card.

The card holds the tooth diagram and every treatment, with the agreed price, what was paid and what is still owed, all written by hand. Appointments go in a book or a spreadsheet, and the day's money is added up at the end.

A card can be misfiled or lost, and anyone who picks it up can read it. Seeing how the month went means going through the cards one by one.

Why we started the MeDoc series with dentists

What we built

One desktop program for the whole practice: patients, the tooth chart, the calendar, documents and money.

  • A tooth chart with all 32 permanent teeth in FDI order, usable by keyboard and named for screen readers.
  • A calendar by day, week or month. In the day and week views you drag an appointment to a new time, and Undo takes it back.
  • Moroccan invoices with the practice's ICE, IF and TP and the total in words, plus prescriptions and medical certificates, printed in French or Arabic.
  • Statistics from the practice's own records, each month compared fairly with the same days of the month before.
  • Automatic daily backups, compressed and encrypted, that can go to a USB stick or an external drive.
  • In Cabinet and Cabinet+, reception sends a chart to the dentist for review, and the dentist sends tasks to reception.

It is sold in three editions, from one dentist on one computer (Essentiel) to up to four dentists on five computers (Cabinet+).

How it works

MeDoc Dentist is a desktop app built with Tauri 2. The screens are written in React and TypeScript. The data, the rules and the documents live in a Rust core.

The code is organised as three systems that each run on their own: the practice app on each computer, a server for the practice network, and a company portal on our side. The Rust code is split into 13 crates, and all three systems share the same core.

Daily work needs no internet connection. All practice data sits in one SQLite database on the practice's computer, encrypted with SQLCipher (AES-256). The key stays in the computer's secure keychain, not next to the data.

In Cabinet and Cabinet+, the practice's computers share that database over the local network. The connection is encrypted and every change is signed. A computer that loses the connection keeps working and catches up when it is back.

Roles and permissions are written once in a configuration file and generated into both the Rust and the TypeScript code. The Rust side enforces them, so a hidden button is never the only protection.

Each edition is built from the same code. What an edition does not include is left out of its build, not just hidden.

GitHub Actions runs the Rust and interface tests on Linux and Windows for every pull request. Release builds are made for Windows, macOS and Linux.

Results

  • About 1,600 automated tests counted in the code: about 1,090 in Rust and about 555 in the interface.
  • 85 end-to-end tests across the three systems, recorded passing in June 2026.
  • Runs on Windows, macOS and Linux.
  • Works without an internet connection: appointments, charts, invoices and backups.
  • Patient data encrypted on disk, and every backup compressed, encrypted with AES-256-GCM and signed.
  • An interface in French, Arabic and English, with Arabic laid out right to left. Every language file holds the same 6,760 keys, checked by a script.
  • Built from April to November 2026, in 195 commits.
