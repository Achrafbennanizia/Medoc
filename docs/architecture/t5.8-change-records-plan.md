Status: **plan; owner decided D1, D2, D5, D8 on 2026-11-27 (recommended options). D3, D4, D6, D7 use the recommended defaults unless the owner changes them.** Nothing is implemented; Phase 1 waits for a go-ahead (breaking sync-protocol change). Source requirements:
editions-plan §0 ("per-author, per-device change records, maintenance view"), §5, §6.5 (History tab),
§6.10 (maintenance view), §6.11 (audit), §6.15 ("History of my records"); owner brief ("follow up and map who

## 1. What exists today (code read 2026-11-27)

| Piece | State | Where |
|---|---|---|
| Write chokepoint for every synced write | one function, has table, id, op and the **full row after the write** | `medoc-core/src/infrastructure/database/recorded_write.rs::record_in_tx` (H2 guard test enforces it) |
| Outbox entry | `device_id, seq, entity_table, entity_id, op, payload_json, created_at`; **no actor** | `medoc-sync/src/repo/types.rs::OutboxEntry` |
| Entry signature | Ed25519 over `canonical_bytes(entry)` (no actor) | `medoc-sync/src/entry_signature.rs` |
| Protocol versioning | `x-medoc-sync-protocol: <v>;min=<m>`, 426 + pause on mismatch | `medoc-sync/src/protocol_compat.rs`, `update_manifest::{SYNC_PROTOCOL, MIN_SYNC_PROTOCOL}` |
| Audit log | hash chain (`prev_hash` + `hmac`), `device_id` column filled; **HMAC key is per device (OS keychain)**; class `DeviceLocal` (not synced) | `repos/admin/audit.rs`, `sync_registry.rs:41` |
| Who is acting | one session per desktop device (`SessionState`); the LAN API writes only profile / app settings | `commands/admin/auth.rs:24`, `medoc-lan/src/http/mod.rs` routes |
| Sharing area for history | `ShareArea::History` already defined | `domain/allowances.rs:25` |
| Health of this device | `health_summary` (version, DB, audit chain, disk, backup age, queue, problems, errors per area) | `commands/system/health.rs` |
| Peers | `sync_device.last_seen_at`; cluster devices with status | `medoc-sync` repo / cluster |
| Logs | channels, redaction, 7-day ZIP export (local only); error refs `ref=<8 hex>` | `infrastructure/logging/`, `commands/system/logging.rs::export_logs`, `error.rs:107` |

Consequences for the design:
- Old and new values do **not** need a new write path: each change already carries the full row after it, so
  "what changed" = difference between two consecutive records of the same row.
- Every device applies every change (full replication, §4.4), so each device can build the history **locally**
  from its own writes plus the entries it applies. No new sync traffic for history.
- The actor is the missing piece, and it must be inside the signed bytes, or a device could forge "Dr A did this".
- A replicated audit chain cannot be checked with today's HMAC (other devices do not have the key).

## 2. Decisions

Decided by the owner (2026-11-27): **D1 (a), D2 (b), D5 (a), D8 yes.** Defaults pending objection: D3 (a), D4 (a), D6 (a), D7 (a).

| # | Question | Options | My recommendation |
|---|---|---|---|
| D1 | Where does the actor come from? | (a) this device's signed-in user, `system` for background jobs, explicit actor for the 2 LAN write routes; (b) pass `actor` through every repo call (hundreds of call sites) | **(a)**: one session per desktop device is how the app works today; smallest change |
| D2 | Which tables get history? | (a) all synced tables; (b) clinical + documents + finance + appointments + tasks + orders (patient-related and money) | **(b)**: that is what § 630f BGB and the cash book need; settings and catalogues stay in the audit log only |
| D3 | How long is history kept? | (a) as long as the record (deleted with GDPR erasure, except where law requires keeping); (b) fixed years per country | **(a)** with the existing retention rules (`infrastructure/retention.rs`): clinical 10 years (DE), never longer than the record |
| D4 | A device that joins later (snapshot): history from before the join? | (a) history starts at join, older rows show "created before this device joined"; (b) ship change records in the snapshot | **(a)** first; (b) later if needed (snapshot size grows a lot) |
| D5 | Audit chains on the hubs | (a) replicate each device's audit rows as append-only, verify each chain by its device's Ed25519 key (sign each row's hash); (b) keep audit local, show other devices' audit only through remote log export | **(a)**: one merged trail for both admins, as the plan says |
| D6 | Error refs | (a) `<device-short>-<ref>` everywhere, parser accepts old refs; (b) keep refs, add device only in the log line | **(a)**: a ref from a replica then points to the right machine (plan §5) |
| D7 | Remote log export from a replica | (a) the hub asks in the next sync reply, the replica uploads a redacted ZIP over the existing blob channel; (b) the hub calls the replica directly | **(a)**: replicas already call the hub; no new listener on replicas |
| D8 | Editions | Duo gets history + device tags + maintenance list too (useful with 3 devices); Group adds per-doctor sharing of history | **yes** (plan §0 says "useful in Duo") |

## 3. Phases (each ends green and stops for review)

### Phase 1: actor in every change (Duo, Group) — **done 2026-11-27**
- `medoc-core/src/infrastructure/database/actor.rs`: author = scoped actor (`with_actor`), else the
  person signed in on this device (`set_device_actor`, called by `SessionState::replace` on sign-in,
  sign-out, idle expiry, licence clear, cluster reset), else `system`.
- The author travels as `syncActor` **inside the payload** of every local change (`record_in_tx`,
  `medoc-sync` `append_outbox`). The payload hash is already in the signed bytes, so the author is
  signed without changing `OutboxEntry` or `canonical_bytes`; stored relay copies still verify.
  Relays and applied entries keep the origin's author (not re-stamped).
- `syncActor` is not a merged field (`field_hlc::is_merged_field`); merges ignore it (not a column).
- Owner-only rows (T4.2): when `syncActor` is present it must equal the owner (`is_owner_signed`).
- LAN API: every request starts as `system`; a staff token narrows it to that staff member.
- Background jobs (start-up repairs, LAN/sync start, log level, work-time close, backups, update
  tick, catch-up, offline sync loop, shared-change thread, reconnect update checks) run as `system`.
- `SYNC_PROTOCOL` = 2, `MIN_SYNC_PROTOCOL` = 2: protocol-1 devices pause with "update needed"
  (they would keep `syncActor` as stray field bookkeeping). `make-update-manifest.mjs` default 2.
- Tests: `medoc-core/tests/actor_stamp_tests.rs` (scoped, delete, system, sign-in/out, not merged),
  `allowances_tests::owner_only_rows_check_the_signed_author`, `entry_signature_tests::altered_author_is_refused`,
  `repo_store_tests::append_outbox_stamps_the_author`, `protocol_compat::protocol_one_devices_must_update`.

### Phase 2: change records + History
- Table `change_record` (DeviceLocal, append-only): `id, table, row_id, op, actor_staff_id, device_id, origin_seq,
  hlc, payload_json (row after), created_at`. Written in `record_in_tx` (local) and where remote entries are
  applied. Only D2 tables. Indexed `(table, row_id, created_at)`.
- Service `application::history`: list a row's records, diff consecutive payloads field by field, hide columns
  in `deny_column`, map ids to names. Sharing: `ShareArea::History` of the row owner (Group); RBAC `audit.read`
  or the record's read permission.
- Commands `history_for_record(table, id)`, `history_for_patient(patient_id)`.
- UI: History tab on the patient record and a History section in the task, order and payment drawers: who,
  which device, when, field: old → new. Group: "not shared by Dr B" note.
- Retention and GDPR erasure (D3) remove records with their row.
- Tests: local write → record; applied remote entry → record with remote actor/device; diff output; hidden
  owner refused; erasure removes history; H2 guard still green.
- **Stop:** review UI in the running app.

### Phase 3: per-device audit chains (Group; Duo if D8)
- Chain per `device_id` (`prev_hash` = last row of the same device). Each row additionally signed with the
  device Ed25519 key (`row_sig`); local HMAC kept for local verification.
- New sync class `AppendOnly` for `audit_log`: insert-only, no updates, duplicates dropped.
- `verify_chain` per device: continuity + signatures; result per device in Help → Support and the maintenance view.
- Audit page: author and device columns, device filter, chain status per device.
- Tests: tampered replicated row detected; gap detected; two devices' chains merge in one list.
- **Stop:** security review (`security-and-hardening`), because this touches audit and crypto.

### Phase 4: device-tagged logs and refs
- Every log line gets `device_id` (short), `edition`, `flavor`, `version` (root span fields).
- Error refs `<device-short>-<8 hex>` (D6); UI `?ref=` pre-fill and support search accept both forms.
- Tests: `log_targets_routed_tests` unchanged; ref parser old/new; support bundle carries the device.

### Phase 5: maintenance view and remote log export (Duo, Group; `cap-maintenance`)
- Replicas attach a compact health block to each sync push (version, last error code and time, disk free,
  backup age, queue depth, open problems); the hub stores it per device.
- Page (Ops → Devices): one row per device: name, role, version, last seen, queue, last error (code + ref,
  linked to the catalogue), disk, backup age; actions: re-pair / revoke (existing), sync problems of that device,
  "Get logs" (D7). Device with an old version or not seen for N minutes is flagged.
- Remote log export: admin only (`ops.logs`), redacted like local export, audited on both devices.
- Tests: health block round trip; stale device flagged; export refused for non-admin; export audited; Solo
  compiles none of it (surface check).

### Phase 6: docs and gates
- Update editions-plan T5.8 status, `docs/architecture/logging.md`, the workflow audit diagram, error catalogue.
- Full gate: cargo test (core, practice, sync, lan, e2e), 5 edition builds, clippy, fmt, vitest, lint,
  i18n parity, surface check, file size.

## 4. Risks

| Risk | Mitigation |
|---|---|
| Protocol change splits a practice mid-update | existing compatibility pause; ship Phase 1 alone; hubs first |
| History table grows | D2 scope, index, retention; measure size on a seeded 5-year DB before Phase 2 ends |
| Write latency (one extra insert per synced write) | same transaction, one insert; benchmark against `perf.log` budget |
| Personal data in history and logs | `deny_column`, redaction, sharing rules, GDPR erasure tests |
| Audit / crypto change | Phase 3 stop for security review; no change to existing local HMAC verification |
